# EmotionScreen V1.0 架构设计

## 目标与范围

构建可迁移的 Python 桌面程序骨架。即使没有麦克风、AI 模型或 GPU，默认模拟模式也能完成端到端演示。第一版提供稳定的模块接口和 Tkinter 界面；真实麦克风和 Clef 服务作为可配置接入点，须在目标设备上完成联调。

## 方案比较

1. **单文件 Tk 应用：** 上手快，但信号处理、网络传输与绘图会互相耦合，后续难以替换。
2. **小型模块化应用（采用）：** 以数据类和接口隔离配置、音频、决策、平滑、视觉映射和界面；不添加数据库、Web 框架、训练组件或推测性的插件体系。
3. **服务化或异步 Web 架构：** 对本地桌面演示没有直接帮助，却会增加部署步骤和运行依赖。

## 模块与数据流

`MockAudioInput` 或可选的 `SoundDeviceAudioInput` 将单声道音频帧放入内存环形缓冲区。`FeatureExtractor` 把最新窗口转换为 `AcousticFeatures`，并在基频不可用时显式保留缺失值和质量标记。调度器按间隔将最新特征交给单个 `DecisionProvider`；同一时刻最多执行一个请求，后续只保留最新快照。`MockDecisionProvider` 支持固定随机种子；`ClefDecisionProvider` 向配置的 `/v1/systemone` 发送 JSON，并严格解析约定的 choice 响应。结果经 `EmotionSmoother` 和 `ReactionController` 转换后，由 Tkinter 绘制。

声音强度走独立的快速视觉通道。HTTP 调用不得运行在 Tk 主线程；音频回调只复制数据，不执行推理。模拟模式不打开麦克风，也不调用 Clef。

## 接口与失败处理

- JSON 配置在加载时校验，不依赖机器专属路径。
- 音频只在内存中处理；不录音存盘、不上传、不识别身份、不作心理诊断。
- 特征以可选值和质量标记表达缺失数据。
- 决策结果区分 `source`、选中情绪、候选概率和 confidence。概率必须校验，Clef 适配器不得自行生成任何概率。
- Clef 响应格式未知、连接失败或超时会显示为错误；模拟模式仍可单独运行。
- 情绪切换经过连续确认和保持时间处理；不确定输入不能伪装成确定的模型结论。
- 关闭窗口时停止定时器并释放音频资源；视觉效果不使用高频闪烁。

## 验证与限制

自动化测试不依赖真实设备或远端模型，覆盖合成信号、无效基频、模拟与 Clef 响应、概率校验、超时、情绪平滑、视觉映射和单请求调度。真实分类准确率仍未知，必须使用合适的标注数据集评估。目标设备上的 Clef 响应契约和音频硬件兼容性尚待确认。
