# EmotiScreen V0.3 音频陪伴链路设计

> 历史版本：描述初版低打扰回应卡。当前常驻毛玻璃/主题渐变/会话预算要求以 `2026-10-08-emotiscreen-ambient-ui-design.md` 为准。

## 产品目标

EmotiScreen 是本地优先、低打扰的桌面陪伴程序。用户明确开启监听后，程序在内存中接收短音频窗，由 NumPy/标准库声学特征分析器估计可观察的声音状态；只有质量合格、满足保守阈值且当前允许回应时，才渐入显示一条本地安抚卡片。

本阶段不使用 ASR。声学状态是实验性估计，不等于用户真实情绪；无法区分悲伤、疲劳、平静等相近声学表现时返回“不确定”并保持安静。用户可选接入本机 Clef，仅用于手工文本开发面板，不处理音频。

## 技术方案

保留 Python、NumPy、Tkinter 和单进程结构。实时音频仍使用可选 `sounddevice` 输入；回调只复制帧到有界队列。窗口线程把足够长的最新音频窗交给单个后台分析线程，忙碌时只保留最新输入。分析线程计算 RMS、短时能量变化、基频统计、过零率、频谱重心和有声比例，随后映射成少量声学状态及未校准规则分，不训练或加载模型。

音频反馈只对“稳定状态从高唤醒转到低唤醒”且音频质量合格的片段建议 `support`；程序启动时就处于低唤醒时只显示状态，不立即弹窗，以免把平静/中性声线误当作悲伤。其他状态（静音、噪声、基频无效或低规则分）均不弹窗。该映射不宣称识别语义情绪；规则分不是概率，真实正确率通过带标签公开音频实测后报告。

## 数据流

`SoundDeviceAudioInput` → 有界 `AudioRingBuffer` → 单工作线程 `AcousticEmotionAnalyzer.analyze(samples, sample_rate)` → `AcousticAnalysis` → `AudioStateTracker`（连续两个窗口确认状态切换）→ `AudioFeedbackPolicy`（只对 elevated→low_arousal 转变响应，并校验质量、规则分、冷却、重复、DND、暂停和窗口占用）→ `ComfortWindow.show(event)`。状态回到高唤醒/不确定时卡片渐隐，避免短时声学波动造成闪烁。单个 WAV 试听仅显示分析状态，不凭孤立窗口触发安抚。系统减少动态效果时立即显示/隐藏。音频、特征及分析结果仅在内存保留，不写盘、不联网。

## 模块边界

- `core/audio.py`：麦克风输入、有界音频环形缓冲。
- `core/acoustic.py`：适配 pyAudioAnalysis 的能量、过零率、谱重心/通量和自相关基频计算片段，输出保守状态估计；不克隆完整工具包。
- `core/audio_runtime.py`：用后台单 worker 承接连续音频窗，只保留最新样本。
- `core/audio_policy.py`：将稳定状态变更门控为本地短回应。
- `core/policy.py`：既有文本策略与音频回应门控；回应均执行去重、冷却、DND、暂停和窗口冲突保护。
- `core/runtime.py`：既有文本决策 worker；音频分析另用单 worker，输入快照不可变，丢弃过时结果。
- `ui/window.py`：显式启动/暂停/停止麦克风，后台分析并把合格结果送入安抚卡片。
- `ui/comfort_window.py`：结合 TkAnimator 的分步透明度/脉冲片段与 CTkMessagebox 的拖动锚点，适配现有 Canvas 卡片、可取消 `after` 任务、减少动态效果和无焦点窗口。

## 失败与安全边界

音频设备不可用、音频过短、削波/静音/噪声、无有效基频、分析异常或结论不确定时不弹窗，并在开发面板显示简短状态。麦克风只在用户启动后开启；停止、暂停、DND 和关闭优先于任何后台结果。没有长期存储、身份推断、诊断或云端音频请求。

## 验收

- 不安装或调用 ASR 即可从麦克风数组得到可解释的 `AcousticAnalysis`。
- 低质量或不确定信号 fail closed；确定性音频输入可覆盖“分析→音频回应策略→`ResponseEvent`”关键路径。
- Tk 运行时仅从后台结果触发 `ComfortWindow`，并实际验证淡入、自动淡出、静态模式。
- 使用 RAVDESS 官方语音样本报告实际声学状态命中情况；数据只在临时目录使用，不提交音频。RAVDESS 为表演式英语情绪语音，不能外推到日常中文对话。
- `python main.py --check` 保留无麦克风、无模型的 Mock 启动检查。
